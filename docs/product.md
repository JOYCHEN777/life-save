# 产品方向

## 已确认

- 核心用途：日常随手记录与查看，帮助记住生活状态。
- 首要体验：每次点击立即获得清晰、愉快的反馈。
- 优先交互：按下时有压感，完成后回弹，时间状态立即更新，并提供可关闭的音效。
- 长期希望覆盖多个平台，第一版允许先从简单形态验证。
- 宠物与世界养成后续考虑；MBTI 个性化、了解自己、寻找合拍的人和活动均不是本轮实现重点。

## 新增需求与设计方向（2026-10-22）

需求收集后，用户已明确授权“先做一版”。以下保留需求与讨论来源，实际交付范围见“当前原型”。

### 用户提出的需求

1. **功能导航**：左侧有可以点开的菜单栏，用于选择功能；具体菜单分组与移动端形态待讨论。
2. **间隔与期望时间**：每项事情可以自定义间隔，显示“距离下一次期望时间还有多久”，以进度条呈现，起到提醒作用。是否需要系统通知、声音，以及后台提醒，尚未确认。
3. **一键确认已完成**：对锁门、直板夹断电、猫咪喂饭、猫咪喂益生菌等事情，主动确认并留下可查看的记录。用户再次担心时，能够看到自己已经确认过，获得安心感。
4. **共同梳理产品**：除用户主动提出的点外，助手也补充使用场景、交互选择和容易遗漏的需求；补充建议不能直接当成已确认范围。

### 已认可的设计方向

用户已认可生活卡片、场景清单、确认凭据和导航的整体方向。首版选择同时支持间隔与每日固定时间，供实际试用后继续调整。

- **统一为可自定义的生活卡片**：每张卡片按需要开启“记录时间”“下次提醒”“完成确认”，避免为每个场景建立一个独立功能。卡片可加入场景分组。
- **确认后留下清楚的凭据**：展示“今天 08:42，你确认过门已锁”，同时保留确认历史。确认记录描述的是用户当时的操作，不能代表设备自动检测到的当前状态。
- **确认归属于具体的一次事情**：锁门、断电可归属于“本次出门”；猫咪照顾可区分早饭、晚饭与益生菌。不要让昨天或上次出门的勾选混成这一次的完成状态。
- **新一轮与旧记录分开**：开启“新一次出门”或进入下一轮照顾任务时，创建新的待确认项，保留旧凭据。何时自动切换、何时手动开启，以及跨午夜的处理，待确认。
- **场景清单**：例如“出门前”包含锁门和直板夹断电，“猫咪照顾”包含喂饭和益生菌；每项可以单独一键确认。整组完成后显示本次清单的结果。
- **首页保留常用入口**：当前场景与常用卡片直接可点；菜单承担功能切换与管理，避免每次记录都要先开菜单。菜单初稿为“首页、场景清单、全部卡片、记录日历、设置”，具体分组仍可调整。
- **提醒与确认可组合**：例如猫咪喂饭卡可同时展示本次是否确认、上次记录和下一次期望时间；锁门卡可以只启用本次出门确认。
- **误触可撤销**：保留默认一键完成的操作路径。

### 讨论时的细节建议（实际交付见当前原型）

- **菜单的平台适配**：桌面端可用折叠菜单，移动端可用抽屉。
- **按场景选择反馈**：普通记录保留清脆的反馈；确认事项侧重清晰、安定的“已确认 + 时间”。不以重复确认次数、连续确认天数设计奖励，不反复催促已经确认的事项。
- **间隔支持两种候选规则**：从上次完成时间向后计算，例如每隔 48 小时；或者按固定时间安排，例如每天 08:00。两种规则对晚做、补记和下一次时间的影响不同，应让用户明确选择。
- **进度条表达时间经过**：间隔开始时为 0%，到期时为 100%，同时显示剩余时间和目标日期。到期后显示“已到期／已超过多久”，不暗示事情自动完成。首次使用没有上次记录时，不虚构起点。
- **可选补充凭据**：照片或简短备注可作为后续选项，不增加默认一键确认的步骤。补记时区分发生时间和录入时间，避免将事后补记显示为当时确认。
- **纠错与暂停**：误触可撤销；提醒可暂停或本次跳过。跳过不计为完成记录，修改间隔时需要说清对当前一轮的影响。

### 后续讨论点

- 最先验证“出门安心”还是“猫咪照顾”；两者是否都需要场景清单。
- 确认按一天、一次出门还是自定义轮次归属；新一轮如何开启。
- 进度条的时间起点，以及只在 App 内展示还是需要离开 App 后也通知。
- 早晚多次任务、临时额外操作、补记与撤销怎样影响当前状态和下一次提醒。
- 若未来需要家人共同照顾宠物，再讨论“谁确认的”、共享状态和避免重复喂食；当前没有共享需求。

## 第一版候选范围

以下保留候选范围。自定义卡片、重复记录、撤销、本地保存与提醒已实现；补记、任意历史修正仍待实现：

1. 自定义生活卡片和名称。
2. 一键记录当前时间，支持撤销误触与补记过去发生的事件。
3. 首页显示上次记录时间与已过去的时长。
4. 查看、修正历史记录。
5. 可靠的本地保存；保存失败时明确提示，不能仅凭动画宣告保存成功。
6. 统一的即时反馈，兼容关闭声音与减少动态效果的偏好。

## 当前原型

已实现可展开的左侧导航，包含首页、场景清单、全部卡片、记录日历和设置。桌面端可收起菜单，手机端使用抽屉；首页直接展示常用记录卡与场景事项。

可新建、编辑生活卡片，设置名称、图标、记录或确认用途，以及间隔或每日固定时间提醒。确认事项可加入“出门前”“猫咪照顾”或作为独立卡片。已有卡片的用途不可切换，避免混淆历史语义；目前不支持自定义新场景、卡片删除或排序。

普通记录卡支持多次新增，每次保存实际点击时间。保存成功后短暂展示反馈，约 0.9 秒后恢复“再记一次”。历史按新增顺序排列，撤销只移除该卡片的最近一次记录，不影响其他卡片。

出门前按手动开启的轮次确认；猫咪照顾与独立确认卡按本机日期每天确认。本轮已确认后展示时间并防止重复确认；新一轮不删除历史。提醒时间与确认轮次分别计算，提醒到期不会自动清除本轮确认。跨午夜后按天确认的卡片重新待确认，手动出门轮次保持，并明确标注开始日期。

间隔提醒从最近一次实际记录计算，无记录时不虚构起点。每日固定时间在当天未记录且已过期望时间时显示到期；当天记录后，下次仍为次日固定时间，不随晚做漂移。进度条在 0% 至 100% 内，显示剩余或已超过的时间。页面每 30 秒及回到前台时更新。关闭页面后不发送系统通知。猫咪早饭、晚饭的 08:00、20:00 及换床单的 7 天为可修改的初始示例规则；过敏药默认不设提醒。

记录区采用类似 GitHub 贡献图的方格日历，按本机日期聚合，默认展示近 12 周，可前后翻页。灰色表示未记录，绿色表示有记录；同一天多次记录不加深颜色。点击日期显示当天的记录数量和具体时间，也可切换为全部记录。今天有轮廓标记，未来日期留空且不可点击；新增和撤销同步更新日历。

记录保存在当前浏览器的本地存储中，刷新后保留；保存失败时不增加记录且明确提示。旧版真实服药记录自动迁移到新版，保留原始 id、时间与旧存储副本；非法或未知版本的数据暂停写入。不同查询参数隔离测试数据，检测多标签页的过时写入，并在支持时使用 Web Locks 串行写入。尚无备份、多端同步和生产级健康数据保障。旧版固定示例不会被当成真实记录迁移。

交互节奏：按压反馈立即开始，持久保存成功后才播放成功反馈；普通记录防连点约 0.9 秒。可关闭音效，选择收敛反馈，并遵循系统减少动态效果偏好。真实手机上的触感与长期使用舒适度仍需用户试用验证。

## 数据与反馈边界

- 记录事件的实际发生时间，补记时间与发生时间应区分。
- 撤销或修正后，重新从有效记录计算“上次发生时间”。
- 保存期间和短暂反馈期间防止意外连点，之后的主动点击可继续新增普通记录；确认事项按本轮状态防重复。
- 用药卡展示距上次服药记录的时间，不能根据没有记录推断没有服药。
- 用药观察依照用户与医生确认的方案，记录客观时间和症状；不把少吃药、延长停药或多次服药设计成得分目标。
- 卡片展示的是记录行为的时间，不自动判断实际服药、剂量或用药方案。

## 待验证

- 高频用户是否能在几秒内完成记录并退出。
- 动画和音效在反复使用后是否仍然舒适。
- 主要入口选择：App 首页、桌面小组件、快捷操作等。
- 首发平台和技术栈，以及原生触感的重要程度。
- 本地数据的备份与恢复方式；是否需要登录与跨端同步。

## 后续方向

真实使用记录形成个人规律；按偏好调整展示和反馈；宠物或世界养成；活动发现与社交。后续功能应在核心记录体验验证后分别评估。
